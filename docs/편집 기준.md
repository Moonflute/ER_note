# ER 초진 Quick Reference 편집 기준

## 1. 용도

- 사용자는 응급실 초진을 보는 인턴 의사다.
- 화면은 차팅 양식이나 종이 기록지가 아니라, 환자 앞에서 빠르게 훑고 확인하는 참고 화면이다.
- 기록은 종이에 하므로 `( )`, `( / / )`, `-/-` 같은 빈 답란을 화면에 만들지 않는다.

## 2. 원문 보존 원칙

- `문진항목 정리/`의 원문 파일을 하나씩 대조해서 정리한다.
- 중복 문구는 합치고 순서는 바꿀 수 있다.
- 원문에 있는 질문, 진찰, 처방, 보고, 차팅 정보를 임의로 없애거나 새로 만들지 않는다.
- 일반적인 문진 순서는 배열 기준으로만 참고한다. 원문에 없는 병력이나 ROS 항목을 보충하지 않는다.
- 뜻이 확인된 약어만 풀어 쓴다. 확인되지 않은 약어는 추측하지 않고 원문을 유지한다.
- 현재 확인된 약어는 다음과 같다.
  - `FCCSR`: Fever / Chill / Cough / Sputum / Rhinorrhea
  - `ANVCD`: Anorexia / Nausea / Vomiting / Constipation / Diarrhea
  - `FUND HIS`: Frequency / Urgency / Nocturia / Dysuria / Hesitancy / Incomplete emptying / Straining

## 3. 상세 화면 구성

상세 화면 순서는 고정한다.

1. `Hx`
2. `PEx`
3. `참고사항`

- `Hx`와 `PEx`는 제목에 다른 설명을 덧붙이지 않는다.
- 여러 원문에 흩어진 공통 항목은 해당 증상의 `Hx` 또는 `PEx` 맨 앞에 둔다.
- `공통 문진`, `복통 문진`, `복통 진찰`처럼 범위를 중복 설명하는 제목을 상세 화면에 표시하지 않는다.
- 소아 자료는 성인 증상에 합치지 않고 `09 소아` 항목 안에서만 사용한다.
- 일반 공통 문진은 `신경과 문진`이라는 독립 항목으로 두지 않고 각 신경 증상에 같은 공유 자료로 연결한다.
- 실제 분과 공통 문진만 있는 항목은 홈에서 `정신과 문진`, `산부인과 문진`, `소아과 문진`처럼 독립 항목으로 둔다.

## 4. 항목 문구 정리

- 질문은 `Chief complaint → Present illness → Past/medication/social history → Review of systems` 흐름으로 배열한다.
- 신체진찰은 `General → HEENT/Neck → Chest → Abdomen → Neurologic/Musculoskeletal` 흐름을 참고하되, 원문에 있는 범위만 사용한다.
- 한 문장에 질문과 지시가 섞여 있으면 질문·소견은 본문에 두고 지시는 작은 회색 주석으로 분리한다.
- 예: `CVAT 반드시 확인`과 `CVAT -/-`는 `CVAT` + `* 반드시 확인`으로 표시한다.
- 의미가 같은 중복 항목은 하나로 합치고 모든 원문 항목 ID를 `sourceItemIds`에 연결한다.
- 한 원문에 서로 다른 질문이 함께 있으면 읽기 어려운 경우에만 나눌 수 있다. 나눈 항목들은 같은 원문 ID를 연결한다.
- 오탈자는 의미가 분명한 경우에만 바로잡는다. 의미가 달라질 가능성이 있으면 원문을 유지한다.
- 의사가 바로 해석할 수 있는 기본 문진은 `V/S`, `CC`, `PI`, `Medical Hx (U/D Drug Adm Op)`, `Social Hx (Alcohol Smoking)`로 표시한다.
- 일반 `CC`에는 onset 확인을 포함하므로 별도 onset 행을 만들지 않는다. 흉통 onset, 외상 시각, last normal time처럼 증상 판단에 필요한 시간 항목은 유지한다.
- `Family Hx / Personal Hx`, `Antiepileptic medication / Last dose time`, `Tetanus vaccination Hx`, `Previous gynecologic care`, `Estimated date of confinement (EDC)`는 축약하지 않는다.
- 안과 과거력은 `OT HX`로 표시한다.

## 5. 참고사항

- 처방, 검사, 관련과·전공의 연락, 환자 설명, 차팅 예시는 `참고사항`에 둔다.
- `인계 메모`라는 제목은 화면에 표시하지 않는다.
- 참고사항은 접지 않고 항상 보이게 한다.
- 내용을 `처방·검사`, `보고`, `증상 조절`, `환자 설명`, `차팅 예시`처럼 실제 사용 순서로 묶는다.
- 원문의 개별 문장을 전부 별도 카드로 만들지 않는다. 연관된 내용은 같은 참고 그룹 안의 목록이나 문단으로 정리한다.

## 6. 화면 밀도

- 체크 수는 증상명과 같은 줄의 오른쪽 위에 둔다.
- Hx/PEx 제목과 항목 글자는 작게 유지한다.
- 체크 행은 한 줄 항목 기준 약 30px 높이, 체크박스는 약 14px를 기준으로 한다.
- 항목 사이의 위아래 여백을 최소화하되 주석은 본문보다 작고 회색으로 구분한다.
- 불필요한 배경색, 장식용 색 띠, 큰 버튼, 애니메이션을 쓰지 않는다.

## 7. 데이터 구조와 검증

- 원문에서 만든 `sections[].items[]`는 수정하지 않는 보존 계층이다.
- 화면용 정리는 각 complaint의 선택적 `layout`에 둔다.
- 모든 화면용 항목은 근거가 된 원문 항목을 `sourceItemIds`로 연결한다.
- layout을 만든 증상은 연결된 원문 항목 전체를 빠짐없이 포함해야 한다.
- 한 원문 파일 또는 한 증상씩 대조하고, 완료한 단위마다 데이터 생성기와 검증기를 실행한다.
- 검사 명령은 다음과 같다.

```powershell
python scripts/curate_data.py
python scripts/validate_data.py
node --check app.js
git diff --check
```

## 8. 배포 작업

- 검증을 통과한 변경은 `main`에 커밋하고 푸시한다.
- 사용자가 직접 확인하므로 별도 요청이 없으면 브라우저 검증과 GitHub Pages 배포 상태 조회는 하지 않는다.
