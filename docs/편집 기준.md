# ER 초진 Quick Reference 편집 기준

## 1. 용도

- 사용자는 응급실 초진을 보는 인턴 의사다.
- 화면은 차팅 양식이나 종이 기록지가 아니라, 환자 앞에서 빠르게 훑고 확인하는 참고 화면이다.
- 기록은 종이에 하므로 `( )`, `( / / )`, `-/-` 같은 빈 답란을 화면에 만들지 않는다.

## 2. 원문 보존 원칙

- `문진항목 정리/`의 원문 파일을 하나씩 대조해서 정리한다.
- 중복 문구는 합치고 순서는 바꿀 수 있다.
- 원문에 있는 질문, 진찰, 처방, 보고, 차팅 정보를 임의로 없애거나 새로 만들지 않는다.
- 일반적인 문진 순서는 배열 기준으로만 참고한다. 원문에 없는 병력이나 ROS 항목을 보충하지 않는다.
- 뜻이 확인된 약어만 풀어 쓴다. 확인되지 않은 약어는 추측하지 않고 원문을 유지한다.
- 현재 확인된 약어는 다음과 같다.
  - `FCCSR`: Fever / Chill / Cough / Sputum / Rhinorrhea
  - `ANVCD`: Anorexia / Nausea / Vomiting / Constipation / Diarrhea
  - `FUND HIS`: Frequency / Urgency / Nocturia / Dysuria / Hesitancy / Incomplete emptying / Straining
- `Td`는 `tenderness`로 정리한다.
- 뜻이 확정되지 않은 `LOM`, `neck level`은 원문 표기를 유지한다.

## 3. 상세 화면 구성

상세 화면 상단은 `문진 | 개념` 탭으로 구성하며, 처음에는 문진을 연다. 문진 탭의 순서는 고정한다.

1. `Hx`
2. `PEx`
3. `참고사항`

- `Hx`와 `PEx`는 제목에 다른 설명을 덧붙이지 않는다.
- 여러 원문에 흩어진 공통 항목은 해당 증상의 `Hx` 또는 `PEx` 맨 앞에 둔다.
- `공통 문진`, `복통 문진`, `복통 진찰`처럼 범위를 중복 설명하는 제목을 상세 화면에 표시하지 않는다.
- 소아 자료는 성인 증상에 합치지 않고 `09 소아` 항목 안에서만 사용한다.
- 일반 공통 문진은 `신경과 문진`이라는 독립 항목으로 두지 않고 각 신경 증상에 같은 공유 자료로 연결한다.
- 실제 분과 공통 문진만 있는 항목은 홈에서 `정신과 문진`, `산부인과 문진`, `소아과 문진`처럼 독립 항목으로 둔다.
- 탭 전환 시 문진 DOM을 다시 만들지 않는다. 체크 상태와 탭별 스크롤 위치를 유지한다.

### 개념 탭

- 응급실의 주요 감별과 문진·진찰의 의미를 빠르게 떠올리는 용도다.
- `감별 → Hx → PEx → 해석 주의 한 문장` 순서로 표시한다.
- 두통·어지럼에 사용자가 요청한 분기형 표시를 먼저 적용한다. 두통은 `발병 속도·양상 변화 → 위험 분기 → 관련 Hx/PEx → 우선 의심 질환`, 이후 이차성 위험 평가를 거쳐 반복되는 일차성 두통 양상을 확인한다.
- 어지럼의 출발 질문은 사용자가 먼저 확인하는 `TRS`로 둔다. `TRS → 지속시간·유발 상황 → 귀·신경 증상 → 안진·보행 진찰`을 표시하고, 답에 따라 필요한 검사와 감별을 연결한다. TRS(+)/(-)만으로 중추/말초를 나누거나 뇌졸중을 배제하지 않는다.
- 흐름의 시작은 해당 CC에서 실제로 묻는 질문으로 잡는다. 질환별 갈래와 검사 적용 조건은 그 답을 해석하는 단계에 둔다. 질문 순서가 지정되면 개념 시작 순서와 문진 layout 순서를 함께 맞춘다.
- HINTS는 지속 AVS+자발안진에서 숙련자가 시행하며, 자세로 새 발작이 생기는 것과 지속 증상이 움직임으로 악화되는 것을 구분한다. 신경증상·보행 위험은 동반 증상/진찰 해석의 앞에 둔다.
- 분기의 `해당 양상 → 추가 확인 → 의심`은 함께 보여준다. 모바일에서는 해당 양상과 추가 확인을 왼쪽, 의심 질환을 오른쪽에 모은다. 관련 Hx와 PEx를 같은 갈래에 붙이고, 근육 압통/경부강직 구분·음성 소견의 한계는 작은 주석으로 보존한다.
- 분기는 감별 우선순위를 보여주는 참고 흐름이다. 여러 갈래가 함께 해당할 수 있고, 위험 단서 부재를 이차성 질환 배제나 일차성 두통 확정으로 표시하지 않는다.
- 선택적 `flow`는 기존 감별/Hx/PEx를 `conceptRefs`로 모두 연결한다. 기존 임상 설명을 보존하고, 흐름의 새 문장에도 근거를 연결한다. 분기마다 체크박스·클릭 선택·접는 메뉴를 추가하지 않는다.
- CC 하나씩 주요 응급 감별·흔한 대체 원인·구별에 필요한 Hx/PEx를 먼저 정한다. 행 수에 맞춰 질환이나 진찰 해석을 누락시키지 않는다.
- 기존 문진의 증상 특이 질문·진찰을 대조해 의미가 빠지지 않았는지 확인한다. 필요한 경우 원문에 없는 핵심 진찰도 근거를 확인해 개념에서 설명한다.
- Hx는 `질문의 답/양상 → 감별 의미`, PEx는 `구체적인 양성 결과 → 의미`로 쓴다. `국소화`, `병변 평가`처럼 결과를 알 수 없는 요약만 남기지 않는다.
- 압통 위치·통증 이동/방사, 유발검사, 동공·반사·청진 결과처럼 감별을 바꾸는 소견을 우선한다. 검사명만 나열하지 않는다.
- PEx는 `소견 → 의심하는 병변/의미`로 쓴다. 정상 소견의 배제 한계와 검사 적용 조건은 필요한 경우에만 명시한다.
- 감별·Hx·PEx·주의 문장에서 같은 설명을 반복하지 않는다. 임상적 정보가 없는 `반드시 확인`, `종합적으로 평가` 등의 문구를 덧붙이지 않는다.
- 임상 핵심을 정한 뒤 반복·군더더기를 압축한다. 전체 표시 문구는 대체로 500자 이하를 목표로 하며, 초과하면 빠질 수 없는 내용과 압축 여부를 `docs/개념 검토.md`에 기록한다. 글자 수를 이유로 핵심 감별·양성 의미·배제 한계·적용 조건을 삭제하지 않는다.
- 개별 설명은 보통 한 문장으로 쓰고, 80자를 넘으면 의미 단위로 나눈다. 글자 크기는 문진과 비슷하게 유지한다.
- 보통의 모바일 한 화면을 목표로 압축한다. 짧은 화면이나 글자 확대에서 필요한 내용이 잘리지 않도록 자연스러운 스크롤은 허용한다.
- 개념에는 별도 체크박스·출처 버튼·접는 메뉴를 만들지 않는다.
- 문진 원문과 분리된 `data/cc-concepts.json`으로 관리한다. 이번에 요청된 신규 의학 설명은 신뢰할 수 있는 외부 근거를 직접 확인하고 추가한다.
- 모든 의학 설명에 `sourceIds`를 연결한다. 자료의 판/장/확인한 절과 공개 본문 범위를 기록한다. 유료 전체 본문을 확인하지 않았다면 완독으로 표시하지 않는다.
- 문진 항목과 연결할 수 있는 설명은 `itemIds`로 연결한다. 원문에 없는 개념상의 진찰/평가를 설명할 때는 빈 배열을 사용하며, 문진 체크리스트에 새 항목을 추가하지 않는다.
- 약어 뜻이 확인되지 않은 `LOM`, `neck level` 등을 개념 작성 과정에서도 추측해 풀지 않는다.
- 변경할 때 제공 중인 CC 전체에서 같은 종류의 누락이 있는지 점검하고 `docs/개념 검토.md`에 CC별 결과를 기록한다. 자동 검증은 임상적 완전성을 보증하지 않으므로 근거 본문과 직접 대조한다.

## 4. 항목 문구 정리

- 질문은 `Chief complaint → Present illness → 증상 특이 문진 → Past/medication/social history → Review of systems` 흐름으로 배열한다.
- 증상 특이 문진은 `CC`와 `PI` 바로 뒤에 두며, 일반 과거력과 ROS보다 먼저 표시한다.
- 소아 증상 화면은 `V/S → 증상 특이 문진 → Birth history → Review of systems` 순서로 표시한다.
- 소아 발열에서는 기본 예방접종력과 발열 직전의 최근 예방접종 여부를 모두 확인한다.
- 분과 공통 문진에서도 현재 증상과 안전에 직접 관련된 질문을 과거력·사회력보다 먼저 표시한다.
- 신체진찰은 `General → HEENT/Neck → Chest → Abdomen → Neurologic/Musculoskeletal` 흐름을 참고하되, 원문에 있는 범위만 사용한다.
- 한 문장에 질문과 지시가 섞여 있으면 질문·소견은 본문에 두고 지시는 작은 회색 주석으로 분리한다.
- 예: `CVAT 반드시 확인`과 `CVAT -/-`는 `CVAT` + `* 반드시 확인`으로 표시한다.
- 의미가 같은 중복 항목은 하나로 합치고 모든 원문 항목 ID를 `sourceItemIds`에 연결한다.
- 한 원문에 서로 다른 질문이 함께 있으면 읽기 어려운 경우에만 나눌 수 있다. 나눈 항목들은 같은 원문 ID를 연결한다.
- 모바일에서 한 행이 지나치게 길어지고 서로 독립적으로 확인할 수 있는 질문은 의미 단위로 나눈다. 선택지·검사 순서·하나의 약어 묶음은 한 항목으로 유지한다.
- 오탈자는 의미가 분명한 경우에만 바로잡는다. 의미가 달라질 가능성이 있으면 원문을 유지한다.
- 의사가 바로 해석할 수 있는 기본 문진은 `V/S`, `CC`, `PI`, `Medical Hx (U/D Drug Adm Op)`, `Social Hx (Alcohol Smoking)`로 표시한다.
- 일반 `CC`에는 onset 확인을 포함하므로 별도 onset 행을 만들지 않는다. 흉통 onset, 외상 시각, last normal time처럼 증상 판단에 필요한 시간 항목은 유지한다.
- `Family Hx / Personal Hx`, `Antiepileptic medication / Last dose time`, `Tetanus vaccination Hx`, `Previous gynecologic care`, `Estimated date of confinement (EDC)`는 축약하지 않는다.
- 안과 과거력은 `OT HX`로 표시한다.
- 간략 보기에서는 기본 문진을 `V/S · CC · PI`와 `Medical Hx · Social Hx` 두 행으로 배치하고 각 항목은 독립 체크 상태를 유지한다.
- 간략 보기에서는 ROS의 `FCCSR`, `ANVCD`, `FUND HIS`를 각각 독립 체크박스로 한 행에 배치한다. 약어에 포함되지 않는 증상은 별도 행에 보존한다.
- 간략 보기는 최초 접속 시 켜진 상태로 시작하고, 이후 선택 상태는 브라우저에 저장한다.

## 5. 참고사항

- 처방, 검사, 관련과·전공의 연락, 환자 설명, 차팅 예시는 `참고사항`에 둔다.
- `인계 메모`라는 제목은 화면에 표시하지 않는다.
- 참고사항은 접지 않고 항상 보이게 한다.
- 내용을 `처방·검사`, `보고`, `증상 조절`, `환자 설명`, `차팅 예시`처럼 실제 사용 순서로 묶는다.
- 원문의 개별 문장을 전부 별도 카드로 만들지 않는다. 연관된 내용은 같은 참고 그룹 안의 목록이나 문단으로 정리한다.
- 날짜나 근무 구역에 따라 달라지는 연락·콜·처방 기준도 원문대로 보존한다. 서로 다른 지시가 함께 있으면 임의로 하나를 선택하지 않고 적용 시점과 조건이 보이게 적는다.

## 6. 홈 분류

- 홈은 `성인 → 소아 → 정신` 세 묶음 순서로 표시한다.
- 성인 묶음 안에서는 `소화기 → 순환기 → 신장/비뇨기 → 산부 → 신경 → 근골격/피부 → 눈/이비인후 → 외상` 순서를 유지한다.
- `입원관리`는 홈 분류에서 제외한다.
- `외상`은 일반 분류의 마지막에 둔다.
- `외상`에는 `상처 외상`, `두부외상`, `흡입화상`, `약물중독`을 둔다.

## 7. 화면 밀도

- 체크 수는 증상명과 같은 줄의 오른쪽 위에 둔다.
- Hx/PEx 제목과 항목 글자는 작게 유지한다.
- 체크 행은 한 줄 항목 기준 약 30px 높이, 체크박스는 약 14px를 기준으로 한다.
- 항목 사이의 위아래 여백을 최소화하되 주석은 본문보다 작고 회색으로 구분한다.
- 불필요한 배경색, 장식용 색 띠, 큰 버튼, 애니메이션을 쓰지 않는다.
- 상세 화면에서 분과명과 범위 배지를 중복 표시하지 않는다. `Basic`, `History`, `Background`처럼 항목 자체로 의미가 드러나는 구조 제목은 화면에서 생략한다.

## 8. 데이터 구조와 검증

- 원문에서 만든 `sections[].items[]`는 수정하지 않는 보존 계층이다.
- 화면용 정리는 각 complaint의 선택적 `layout`에 둔다.
- 모든 화면용 항목은 근거가 된 원문 항목을 `sourceItemIds`로 연결한다.
- layout을 만든 증상은 연결된 원문 항목 전체를 빠짐없이 포함해야 한다.
- 한 원문 파일 또는 한 증상씩 대조하고, 완료한 단위마다 데이터 생성기와 검증기를 실행한다.
- 검사 명령은 다음과 같다.

```powershell
python scripts/curate_data.py
python scripts/validate_data.py
python scripts/validate_concepts.py
node --check app.js
node --check sw.js
git diff --check
```

## 9. 배포 작업

- 검증을 통과한 변경은 `main`에 커밋하고 푸시한다.
- 사용자가 직접 확인하므로 별도 요청이 없으면 브라우저 검증과 GitHub Pages 배포 상태 조회는 하지 않는다.
- 서비스 워커는 앱 셸·정적 데이터·아이콘을 로컬 캐시에 보관한다. 정적 데이터는 네트워크 응답을 우선하고 실패할 때 캐시를 사용한다.
- 앱·스타일·데이터 버전을 변경할 때 `index.html`, `app.js`, `sw.js`의 캐시 버전을 함께 갱신한다.
